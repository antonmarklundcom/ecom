## 7. Things the next manager should know

- A cloud session that has been allowed to message a session on Anton's computer becomes limited
  to his trusted devices, and from then on **cloud child sessions cannot send it messages**
  (O36's report was lost that way; it is in `docs/log/o36.md`). A manager should either not ask
  for that permission, or read results from the repos on a scheduled check instead of waiting
  for reports.
- A cloud session cannot push tags and cannot create repositories.
- Cloud sessions can run MariaDB (`apt-get install mariadb-server`), so the full gate runs
  locally; `ecom` is public, so its GitHub checks cost no minutes. Store repos are private:
  their checks use Actions minutes.
- Parallel phases worked: three at once, the manager merging one PR at a time and each later
  PR pulling in the merged ones. The proof phase at the end found five real defects that the
  per-phase checks had missed, all in "a store that is not the template".
