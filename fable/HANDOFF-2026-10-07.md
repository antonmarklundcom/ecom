## 5. How to run things in a fresh container (pitfalls already paid for)

- Docker isn't running at container start. Start it with
  `dockerd > /tmp/dockerd.log 2>&1 &`. Then:

  ```bash
  docker run -d --name ecom-mysql8 -e MYSQL_ROOT_PASSWORD=root -e MYSQL_DATABASE=ecom \
    -p 127.0.0.1:33068:3306 mysql:8 --character-set-server=utf8mb4 --collation-server=utf8mb4_unicode_ci
  docker run -d --name ecom-mariadb -e MARIADB_ROOT_PASSWORD=root -e MARIADB_DATABASE=ecom \
    -p 127.0.0.1:33069:3306 mariadb:10.11
  ```

- Database names must contain `test`. Use a different `TEST_DATABASE_URL`
  database per worktree.
- Run suites with `pnpm test` (it sets `npm_execpath`), **not**
  `pnpm vitest`.
- Run browser specs with nothing else on the same MySQL server, or
  storefront specs time out.
- Prepare a browser database with `pnpm db:migrate` and then
  `pnpm exec tsx scripts/prepare-browser-tests.ts`. That script **requires
  `DATABASE_URL == TEST_DATABASE_URL`** and truncates every table.
- Shell pitfalls:
  - In `cd X && (a) & (b) & wait`, only `(a)` runs in `X`. Use one command
    per background job.
  - `pkill -f pattern` kills your own shell when the pattern is in the
    command line. Use `pgrep -f "[p]attern"`.
- Formatting: only run Prettier on files that were Prettier-clean before,
  so the diff doesn't fill with formatting. Several files (e.g.
  `src/db/enums.ts`, `src/app/actions/admin-ajustes.ts`) are intentionally
  not Prettier-formatted.
- Static guard tests to keep green:
  - dead i18n keys (only `src/` is scanned);
  - `pnpm i18n:client` after adding client keys;
  - no hand-built `wa.me` links;
  - `orders.status` is written only by `transitionOrder`;
  - every server action is listed in `tests/unit/admin-guards.test.ts`;
  - e2e specs must not mention seed names or slugs
    (`testids-contrato.test.ts`);
  - the store name is never hard-coded (`marca-centralizada`).
- MySQL **rounds** fractional seconds and MariaDB **truncates** them;
  compare timestamps with ±1 s.
- Harness (`fable/harness-tiendas/`):
  - Copy it to a work dir and `export HARNESS_DIR=<dir>`.
  - Put a bare full clone of the template at `$HARNESS_DIR/stores/tpl.git`
    (`git clone --bare https://github.com/antonmarklundcom/ecom.git`),
    with `main` pointed at the template version the stores should start
    from.
  - Put a checkout of the target template version with `node_modules` at
    `$HARNESS_DIR/wt-main`.
  - Create `$HARNESS_DIR/env-e2e.sh` from `env-e2e.example.sh`. Generate
    the values **once**, then paste them as literals.
  - The scripts expect to be run from `$HARNESS_DIR/stores`.
  - **None of the store repos or databases from this session survive:** the
    container is reclaimed. Recreating them takes about 15 minutes with
    `mk_store.sh` and `populate_t0.sh`, with the flags listed in §3.
- Commits end with the trailer lines the session's system prompt gives.
  Never put a model name in commits or PRs.
- The user allows merging PRs once local gates are green. There's no live
  site: never deploy, never touch production, DNS or accounts.
