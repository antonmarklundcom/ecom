# S29 — faster new store (2026-11-11)

PR #178. Sonnet 5.5. Prompt `fable/prompts/sonnet-29-new-store-speed.md`, plan `fable/plan-2026-11.md` §6.3. Branch `phase/s29-new-store`. Nothing was created on GitHub, Hostinger or Cloudflare: `gh` is never run by the tests, and no `--crear-repo` / `registrar-tienda` ran for real.

## Built
- `pnpm nueva-tienda --crear-repo <dueño/nombre> [--publico] [--en <carpeta>]`: `gh repo create --template antonmarklundcom/ecom` (`--private` unless `--publico`), `gh repo clone` (retried: a fresh template repo takes seconds to fill), `git remote add template`, `gh label create ci-completo --force`, `pnpm install --frozen-lockfile`, then the existing wizard in the clone with the other flags passed through. `--dry-run` prints the list and runs nothing. The command list is a pure function (`pasosCrearRepo`); every child process gets an environment with all `GIT_*` removed (`envSinGit`).
- `pnpm registrar-tienda <dueño/nombre> [--anillo 0|1] [--estado activa|pausada] [--dominio] [--notas] [--dry-run]` (new `scripts/registrar-tienda.ts`, run in the template): adds the entry to `tiendas.json`, validated by the same `leerTiendas` the workflow uses, on branch `registrar-tienda/<owner>-<name>`, commits, pushes and opens the PR with `gh pr create`. Refuses a dirty checkout or a repo already listed. Prints (and puts in the PR body) the one manual step left: give `TIENDAS_TOKEN` access to the repo.
- The wizard writes git-ignored `HOSTINGER-CHECKLIST.md`: database (suggested name from the domain), repo/deploy key, the five env keys plus `NODE_ENV`, domain/Cloudflare grey cloud, `/setup`, the three cron lines with the store's domain, health check. No secret value: each secret says which `.env.local` key to copy. `.gitignore` has the file.
- Docs: NEW-STORE.md "En una página" rewritten (14 lines / 663 characters, was 15 / 826), §1 and §2; CHANGELOG "Sin publicar".
- Tests: `tests/unit/nueva-tienda-repo.test.ts` (command line, private/public, clone, remote, label, wizard last, flag validation, checklist content and no secrets, `.gitignore`, a real `--dry-run` CLI run) and `tests/unit/registrar-tienda.test.ts` (parsing, entry validation, PR body, command order with `gh`/`git` mocked, dry-run, dirty checkout, a real `--dry-run` CLI run that leaves `tiendas.json` untouched).

## Decisions
- Review Q6 (store repos public or private) is unanswered: repos are created **private** by default, `--publico` chooses public. Private repos cost CI minutes (about 18 minutes per store per release, review point 7); this stays Anton's call.
- `registrar-tienda` defaults to anillo 1, `activa` (same as an entry without the fields); `--estado pausada` is one flag. All three existing stores stay `pausada` and this PR does not change `tiendas.json`.
- `--crear-repo` clones to `../<nombre>` (next to where it runs); `--en` overrides.
- The checklist builds `DATABASE_URL` from a template (`mysql://USUARIO:CONTRASEÑA@HOST:3306/BASE`) and never contains a credential; the database name is a suggestion (Hostinger prefixes `uNNN_`).

## Known issues
- Hostinger's side is still clicks: no API is used (the connector was never authorised). The checklist only removes the guessing.
- `--crear-repo` is not idempotent after the repo exists: a rerun fails at `gh repo create`. Finish by hand from the clone (`pnpm nueva-tienda`) or delete the empty repo.
- `registrar-tienda` needs `origin` of the template checkout to be writable by the `gh` user; it does not set the token access (that is the manual step, GitHub offers no API for a fine-grained token's repo list).
- `scripts/template-shared.ts` `gitEn` still inherits `GIT_*` (another PR owns it); nothing S29 added uses it.

## Manual steps left for a new store (honest estimate)
GitHub and wizard: 5 minutes (was about 20). Token access: 2 minutes. Hostinger database, site/deploy key, variables, Redeploy, `/setup`, three cron lines: 35–40 minutes with the checklist (was about 55; no API call, still clicks). Domain/DNS: 15 minutes plus propagation. R2 bucket and keys: 15 minutes. Pagopar and bank data: 30–60 minutes plus days for third parties. Preflight and smoke test: 10 minutes. About **1.5–2 hours of plumbing** instead of about 2.5; the gain is in GitHub, the guessing and the transposed-column mistakes, not in Hostinger. Estimate, not timed.
