## Built
- `src/lib/guias.ts`: a guide is `src/content/guias/<slug>.md` (front matter + markdown). Its own parser for a small YAML subset (scalars, `[a, b]`, `- a`, `- key: value` pairs); unknown keys, `|` blocks or odd indentation are errors, not guesses. Content rules (`problemasDeGuia(s)`), `slugsDesconocidos`, folder reading (README and non-`.md` ignored; a missing folder = no guides), memoised per process; broken or invalid published files are skipped with `log.error`, never break a build.
- `src/lib/markdown-guia.ts`: the guide renderer on `markdown.ts`'s rule (escape everything first; no raw HTML): h2–h4 with ids (`#` drops to h2), paragraphs, bold/italic, `-` and `1.` lists, pipe tables, block quotes; links only `https://` (`nofollow noopener`, new tab) or internal `/…` (followed).
- `/guias` (index) and `/guias/<slug>`: `force-static`, ISR 300, `generateStaticParams` + `dynamicParams = false`; drafts are built only outside production (404 in production). Canonical, Open Graph `article`, `Article` + `BreadcrumbList`. The guide shows its categories (chips) and products (cards); unknown slugs are skipped and logged (`log.warn`). FAQ shown as `<details>`, sources as `nofollow` links.
- `Article`: headline, description, `datePublished`, `dateModified`, author and publisher = the store (`marcaEfectiva()`, logo if https), `mainEntityOfPage`, `url`, `image` only if the guide has one. No person, rating or `FAQPage`.
- `src/lib/seo.ts`: own block `guiasSitemap` + `articleJsonLd`; `src/app/sitemap.ts`: guide entries appended in their own block (index with the newest `actualizada`, one per guide), also when the database is down.
- Links back: "Guías relacionadas" on category and product pages (guides naming them), home section `guias` (three newest; in `SECCIONES_HOME`, in the base and `vitrina` orders, a theme can move or drop it), footer link "Guías" (both footer variants). All off with zero published guides.
- `scripts/template-shared.ts`: `src/content/` is the store's (`CARPETAS_DE_LA_TIENDA` via `esDeLaTienda`: sync keeps what the store has, brings only what it lacks); `src/app/guias` is mixed; `src/lib/guias.ts` is machinery (`src/lib`). `pnpm nueva-tienda` deletes only `SOLO_TEMPLATE`, so `src/content/` stays.
- Docs: `docs/GUIAS.md` (format, decision 8, editorial rules, the test's checklist), `src/content/guias/README.md`, NEW-STORE.md §5 rows, CHANGELOG bullet.
- Tests: `guias-formato` (parser, rules, limits, folder), `guias-markdown` (renderer + XSS payloads), `guias-seo`, `guias-template` (classification, `decidirArchivo`, `nueva-tienda`), `guias-contenido` (the content test that travels: reads the store's `src/content/guias/`, reports the slugs it names); integration `template-sync.test.ts` "src/content/ es de la tienda" (real git: a store's guides survive two syncs, including a template file with the same name and the template deleting its README); e2e `tests/e2e/guias.spec.ts`. Fixtures in `tests/fixtures/guias/` (2 published, 1 draft, 2 invalid in `invalidas/`).

## Decisions
- No dependency for front matter or markdown: the subset is small and the renderer is the one place that feeds `dangerouslySetInnerHTML`.
- Unknown slugs are not a test failure (the test cannot see a store's database): the content test prints them as a report, the page skips them, the server logs them.
- `GUIAS_DIR` is a test hook, honoured only inside `tests/fixtures/`; CI's e2e job sets it (`.github/workflows/ci.yml`, one env line), so a store's e2e runs the fixture guides too. The zero-guide case is a spec branch that runs when the build has no guides.
- `src/proxy.ts` `RUTAS_CACHEADAS` gains `/guias` and `/guias/[slug]`: static HTML without a nonce, otherwise the pages ship dead (`csp-isr.test.ts` enforces it). `tests/unit/seo.test.ts` lists `guias` as public.
- With O32's store mode: the guide page passes `modoVentaEfectivo()` to its product cards (in "consulta" a stock product reads "Consultá disponibilidad", no cart); guides, home block and footer link do not depend on the mode. A panel switch re-renders the guides too (`revalidarVidriera` revalidates the whole layout). Unit guard + e2e in both modes.
- Product page shows guides that name the product only, not its category's guides ("the guides that name it").
