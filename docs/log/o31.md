## Decisions
- Brand guard: "Productos" is ordinary vocabulary all over the template, so `marca-centralizada` and the default-texts test of `store-settings` failed in the store from its first commit. The store's `tienda.ts` got an optional `marcaBuscable` (`productos.com.py`) that both guards search when present. Resolved in the store as a minor issue (plan §4.4), and proposed to the template with the same name so a sync converges (proposal 1).
- `header-category-link`: the template's e2e specs click the first one; the skin had them only inside the closed dropdown/drawer, so 19 specs hung (CI e2e hit its 10-minute limit). One always-visible scrollable strip carries the id; the hidden copies do not.
- Home keeps the live rule: "Destacados" always (hand-picked, else the first catalogue products) and "Novedades" always.
- Supplier offers keep D1's `updated_at` (2026-10-09, the only capture date; D1's `checked_at` is empty on purpose: "históricos… pendientes de verificar"). No `checked_at` invented.
- The Lab cross-check reads the store side from the D1 export (what the import writes), so it runs without a database.
- Store-settings keys unknown to the template are reported and dropped; integration settings are not imported (secrets encrypted with the Worker's `SESSION_SECRET`).
- Header keeps the template's cart, wishlist and "Seguí tu pedido": the live site is catalog-only, the new store sells.
