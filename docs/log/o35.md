- Tests: `tests/unit/disponibilidad.test.ts` (every §2.4 row, one-source check), `src/components/__tests__/disponibilidad.test.tsx` (line = Offer for each word), `tests/unit/seo.test.ts` (O35 blocks), `tests/unit/seo-auditar.test.ts` (checks; guides present/absent), `tests/integration/o35-seo.test.ts` (page rendered with `proveedores: true`, no supplier field in the HTML; feed; sitemap photos; `categorias:aplicar` dry run/apply/rerun/`--pisar`/refusals), `tests/integration/seo-auditar.test.ts` (demo data, `--estricto` exits 1).

## Decisions
- Pure rule and DB reader are two files, so `src/lib/seo.ts` (imported by the layout) never pulls the database; the reader is on the `proveedores-privados` allowlist.
- Enquiry products keep `available: 0` from the public queries (their warehouse stock is not public), so "own stock" in practice counts for `stock` products, also in consulta mode.
- The product card is unchanged: it has no supplier data and a guess would contradict the page. Its line stays "Consultá disponibilidad…".
- `productJsonLd` without the `disponibilidad` map (old callers, tests) applies the same rule without supplier data.
- `categorias:aplicar` without `--pisar` fills an empty parent too; position and name change only with `--pisar`; a text absent from the file never clears the database.
- `seo:auditar` loads `src/lib/guias.ts` by path when it exists (O34's `leerCarpetaDeGuias`, `problemasDeGuias`); category "no guide" is checked only then.
- Sync: `src/app/contacto/page.tsx` is skin. productos.tienda: if it has its own `src/app/contacto/`, `template:sync` keeps it (`conservar`, listed as "tuyos"); if not, it receives this page. A redesigned footer does not get the link.

## Known issues
- The guide checks were built against O34's API on its branch (`6492f7a`); re-run `pnpm seo:auditar` once O34 is on `main`.
- Card and product page can disagree when a supplier confirms stock (card: "consultá", page: "En stock"); harmless, noted for §10.
