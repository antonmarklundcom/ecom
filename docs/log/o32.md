## Decisions
- The pure rule lives in a new `src/domain/modo-venta.ts` (not `src/lib/modo-venta.ts`), so client components (card, wishlist) can import it without pulling the database.
- The card cannot read settings (it also renders client-side), so it takes a `modoVenta` prop; home, search, category and product pages pass it. These four pages and the footer/404/dashboard are outside the prompt's Owns list, touched only to pass the mode or hide an order link.
- JSON-LD and the product feed still use the raw `sale_mode` (structured data is O35 per the prompt).
- In carrito the panel WhatsApp does not replace `WHATSAPP_NUMBER` in preflight (it is also the owner-notice destination); in consulta it does.
- Mode is chosen only by flag in `nueva-tienda`, not asked interactively.
- No existing test or spec changed its expectation; the e2e specs only swapped the category click for `irAPrimeraCategoria()`.

## Known issues
- `/api` cart quote and `/comparar` still price stock products in consulta (harmless: no cart entry point, order refused).
- Related products on the product page require stock, so in a consulta store with stock 0 the section is empty.
- Local gate note: Playwright must run after seeding **then** building (CI order); building before `prepare-browser-tests` leaves prerendered category pages with stale variant ids. The cloud container's Playwright needs `PLAYWRIGHT_CHROMIUM_EXECUTABLE=/opt/pw-browsers/chromium`.
- `next build` stopped once with Next's "SecurityFatalError" advisory notice for Next 16.4.3; a retry builds. Upgrading Next is not this phase (backlog).
